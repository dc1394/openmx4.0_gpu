## ビルドと実行

ホストには CI と同じ apt パッケージがありません。足りないのは `libomp-dev`、`openmpi-bin`、`libopenmpi-dev`、`libscalapack-openmpi-dev`、`libfftw3-dev`、`libtool-bin` で、`sudo` にはパスワードが要ります。CPU 版は、同じパッケージを入れた Docker イメージ `openmx-cpu-toolchains:ubuntu24.04` の中でビルドして実行します。イメージの中身は Ubuntu 24.04.5、GCC 13.3.0、Open MPI 4.1.6、OpenBLAS 0.3.26、ScaLAPACK 2.2.1、FFTW 3.3.10、CMake 3.28.3 です。イメージがなくなった場合は、Ubuntu 24.04 に `.github/workflows/core.yml` の `cpu-application` と同じパッケージを入れて作り直します。

```sh
# リポジトリーのルートで実行する。コンテナにはリポジトリーを同じパスで見せる
D="docker run --rm --user $(id -u):$(id -g) -e HOME=/home/ubuntu -e OMP_NUM_THREADS=1 -e OPENBLAS_NUM_THREADS=1 -v $PWD:$PWD"
IMG=openmx-cpu-toolchains:ubuntu24.04
$D -w $PWD $IMG cmake -S . -B build/exx-cpu -DOPENMX_GPU_BACKEND=CPU -DOPENMX_CPU_COMPILER=GCC \
  -DOPENMX_CPU_MPI=OPENMPI -DOPENMX_CPU_LINALG=OPENBLAS -DOPENMX_COPY_TO_WORK=OFF -DOPENMX_BUILD_JOBS=8
$D -w $PWD $IMG cmake --build build/exx-cpu --parallel 12
$D -w $PWD $IMG ctest --test-dir build/exx-cpu --output-on-failure \
  -R '^(core-(grid-assembly|host-simd-boundary)|build-backend-isolation|cpu-build-accelerator-boundary|cpu-numerical-toolchain|environment-registry)'
# 実行例。build/exx-m0/DFT_DATA19 は ../../DFT_DATA19 へのシンボリックリンク
$D -w $PWD/build/exx-m0/run_after $IMG mpirun -np 1 ../../exx-cpu/openmx Methane.dat
```

初回のビルドは 12 並列で約 5 分です。

大域状態のゲートはホストで実行します。この計算機の `source/third_party/gpusolver2-install` には OpenMP 版 ELPA のヘッダーがないので、CMake の CUDA ステージのスタックを指定します。指定しないと `elpa_cosma_bridge.c` と `openmx_elpa_cpu.c` が解析されません。

`-DOPENMX_COPY_TO_WORK=OFF` を付けないと、ビルドのたびに実行ファイルが `work/openmx` に複写されます（ルートの `CMakeLists.txt` の `OPENMX_COPY_TO_WORK`。既定は `ON`）。2026-11-23 の記録では、利用者の計算機の `work/openmx` は GPU 版の実行ファイルで、`build/cuda` には CUDA 版のビルドがあります（「決めたこと」と、この節の大域状態のゲートのコマンド）。どのコミットのものかは、記録にありません。この 2 つを書き換えないように、複写を止め、別のディレクトリーにビルドします。`8cdb5da` までの版の手順には、この指定がありませんでした。

CPU 版と CUDA 版を別の環境で実行する場合は、`run` を 2 回に分けます。先に、CPU 版の 6 件を名前で指定して実行します（`ch4-cpu` など）。次に、名前を付けない `run` で残りの 12 件を実行します。`--gpu` は必須の引数ですが、CPU 版の実行では使いません。`results.json` の `_machine` は最後の `run` が書くので、GPU のある環境を後にします。2 つの `run` を同じ出力先で同時に動かすと、互いの結果を上書きして失います。

系は 6 つで、系ごとに 3 つの実行があります。`NAME-cpu` は CPU 版、`NAME-gpu` は CUDA 版です。`NAME-host` は、CUDA 版に `OPENMX_GPU_CAPACITY_TEST_RECOVERY=1` を付けた実行で、大きい積を全てホストに残します。`run` に名前を付けると、その系か、その実行だけを行います。`--mpirun` は起動のコマンド、`--threads` はプロセスあたりのスレッド数です（既定は 2）。`run` は、`nvidia-smi` が返すデバイスの名前を `results.json` に記録します。

`table` は、系ごとに 3 つのことを表示します。1 つ目は、CUDA 版と CPU 版の全エネルギーの差です（閾値 1e-7 Hartree）。2 つ目は、デバイスで計算した積の数と、容量の不足でホストに残した積の数です。`siz-p444`、`siz-p444-np2`、`diaz-p222` では構築 1 回に 4 個、`siz-p444-spin` では 8 個を予定しています。この数と違うと、行が失敗になります。3 つ目は、段ごとの時間です。`table` の出力と `build/exx-m6/results.json` が、受け入れ試験の記録になります。

CPU 版の実行の時間は、このコンテナ（4 コア、2 スレッド）で、`siz-p444` が 100 秒、`siz-p444-spin` が 184 秒、`siz-p444-np2` が 54 秒でした。`diaz-p222` は 473 秒です（M5 の実測）。18 件の合計は、3 つの実行が同じ速度なら 41 分になります（計算値）。`diaz-p222` は、ホストのメモリーを 1.4 GB 使います（M5 の実測で 1,361 MB）。

CUDA 版の標準出力では、計算の終わりの `<EXX>  GPU:` で始まる行が、デバイスで計算した積の数を示します。この行は、CPU 版と、デバイスに送る大きさの積がない計算では出ません。`level.of.stdout 2` を指定すると、構築ごとに、ランク 0 の積の数と、1 個の積がデバイスで使った量の最大を表示します。
