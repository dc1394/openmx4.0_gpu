# Environment variables of the GPU build

Generated by `tools/env_registry_doc.py` from `source/openmx_env_registry.h` and `doc/environment_variables.json`;
do not edit by hand. Every setting is read once after `MPI_Init` (`source/openmx_env.c`): rank 0's values reach
every rank, a misspelt `OPENMX_*` name and a value that does not parse for its kind are reported once, and
`level.of.stdout 2` lists the settings in effect. A flag accepts a number (nonzero = on), `on`/`yes`/`true`
and `off`/`no`/`false`; `auto`, an empty value and an unset variable select the default.

## Device binding and device-memory accounting (set_cuda_default_device_from_local_rank.c)

| Variable | Default | Meaning |
|---|---|---|
| `OPENMX_GPU_STACK_BYTES` | the largest stack frame of OpenMX's own kernels (cuobjdump on the linked binary at link time; 1000 bytes in the current build) | Per-thread kernel stack limit set at device initialization (`cudaLimitStackSize`, `OpenMX_GpuPresizeKernelStack`) when it exceeds the driver's default 1 KiB, so the driver sizes the context's local-memory pool while the device is empty instead of at the first launch of a kernel with a large frame. That launch-time growth (about 26 MiB per context for a 1224-byte frame on an RTX 5080: (frame − 1024) × every resident thread of the device) raced with the force-phase arenas, which fill the device down to their reserve, and lost at 18 ranks on 16 GB (`cuLaunchKernel`: out of memory in `Force3_GpuTrace`, C1000, whose dOrbitals kernel had that frame; its spherical-harmonic tables are now flat, 936 bytes, so the step is idle at present). The Makefile reads the figure from the linked binary (the kernels of the objects; the linked libraries' kernels, such as ELPA's 1328-byte one, are not counted) and relinks once with it. 0 disables the step; a raised limit costs (limit − 1024) × resident threads of device memory per rank. |
| `OPENMX_GPU_MEMINFO_NVML` | 1 | Every device-memory budget of the GPU paths starts from `OpenMX_GpuMemGetInfo()`: `cudaMemGetInfo()` with the free figure capped at the memory that is physically free according to NVML. On WDDM platforms (WSL2) the CUDA runtime reports a per-process view in which the other ranks' contexts and arrays are invisible, and an allocation past the physical memory is paged through system memory at a fraction of the speed instead of failing: 12 ranks on a 12 GB RTX 4070 Ti each saw 10.8 GiB "free", took 836 MiB each for the DS_VNA batch and stalled Set_ProExpn_VNA for minutes (0.6 GiB was left after the contexts). On Linux the two figures agree. A one-time stdout notice (level.of.stdout 2 and above) reports both figures when they differ by more than 256 MiB. 0 = plain `cudaMemGetInfo()` |
| `OPENMX_GPU` | 1 | Master switch of the GPU paths: **0** keeps every rank on the host code even with `scf.eigen.lib=gpusolver` (the device probe, the multi-GPU pool and the capacity workers all read it). |
| `OPENMX_GPU_PROBE_RESERVE_MB` | 256 | Free device memory a rank must still see right after creating its own context before it may claim the GPU: headroom for the device-module load (which aborts, not fails, when it cannot allocate) and for the runtime's transients. |
| `OPENMX_GPU_RANK_MAP` | block | Rank-to-device map of a node: by default consecutive node-local ranks share a device in blocks (ranks per device = ceil(local ranks / devices)); a value starting with `m` (modulo) assigns `local_rank % devices` instead. |

## Refined FP32 eigensolver (eigen_refine_gpu.c)

| Variable | Default | Meaning |
|---|---|---|
| `OPENMX_EIGEN_REFINE` | 2 on GPUs whose FP32:FP64 throughput ratio is at least 8 (GeForce, RTX PRO 6000 Blackwell, ...) when the GEMMul8 products of the solver's kind (real for collinear, complex for noncollinear) are on; else 0 | Cluster dense paths (collinear, per spin; noncollinear) and the band solvers (one k-point per rank: the estimates of all k-points are gathered before the refinement; several k-points per rank: the first pass refines with the previous step's chemical potential and keeps the basis on the host, bounded by `OPENMX_BAND_REFINE_BASIS_MB` per rank (default 1024), and the second pass refines from it with the step's chemical potential): K > 0 solves all n (2n) pairs in FP32 and refines the MaxN wanted ones by K Ogita–Aishima steps (products through GEMMul8, module `eigen_refine_gpu.c`) plus a Rayleigh–Ritz step in partially occupied clusters; from the second SCF step on the refinement starts from the previous step's vectors when they are within 2e-5 of the new Hamiltonian (`OPENMX_EIGEN_REFINE_WARM`). The step that ends the SCF is solved once more in FP64, the last step `scf.maxIter` allows is FP64. With spin polarization the two spin worlds' owners exchange their eigenvalue estimates for the chemical potential (the band solvers gather the estimates of all k-points before the refinement); a single rank solving both spins, the serialized spin mode, XANES and emptied orbitals or states keep FP64. **0** = off. On an RTX 5080 (18 ranks) noncollinear sidia333 (2n = 5616) takes 197.9 s instead of 261.3 s with the same SCF steps The band solvers refine the maxn wanted columns and rotate the other n − maxn columns against them every step (`OPENMX_EIGEN_REFINE_COMPLEMENT`, default 1): left alone, their FP32-level components along the occupied subspace tilt the refined columns' fixed point out of it by about 1e-8, which cost 2 to 5 extra SCF steps and biased warm starts. When the k-owners do not fit in one GPU turn group, the one-k-point-per-rank solves are staged like the multi-k-point ones (pass 1 with the previous step's chemical potential and the basis on the host, pass 2 from it), so a 16 GB card refines them too. Diagnostics: `OPENMX_EIGEN_REFINE_CHECK=1` prints the residuals and orthogonality of the refined columns by occupation class with plain FP64 products, `OPENMX_EIGEN_REFINE_ALL=1` refines every column |
| `OPENMX_EIGEN_REFINE_UNTIL` | 0 (off) | Printed NormRD below which the refined eigensolver hands the rest of the SCF cycle to the FP64 eigensolver. Off by default: an SCF that ends on a refined step has that step's Hamiltonian solved once more in FP64 (one eigensolve, no density matrix) for the vectors the post-SCF energy density matrix and the forces are built from Invalid (NaN/Inf) refinement products, eigenvalues or final vectors now reject the refinement before it overwrites the preserved FP64 matrix. This safety check does not change the successful arithmetic or tolerances.  |
| `OPENMX_EIGEN_REFINE_WARM` | 1 | Warm start of the refined eigensolver: the vectors of the previous step's refined solve are refined against the new Hamiltonian instead of solving in FP32 first, as long as their residual on it is at most 2e-5 (sidia333 on an A100: the eigensolver phase 706 -> 140 ms per step, 20 of 22 steps); **0** = an FP32 solve every step The band solvers warm-start too (`OPENMX_EIGEN_REFINE_WARM_BAND`, default 1); `OPENMX_EIGEN_REFINE_WARM_PERIOD`=N makes them solve in FP32 again every N SCF steps (default 0 = never: since the unrefined columns are rotated against the refined ones, a chain of warm starts agrees with FP64 to 2e-12 Ha on sidia333) |
| `OPENMX_EIGEN_REFINE_STOP_GUARD` | 100 | An SCF stop on a refined FP32 step also needs the printed NormRD below this factor times `scf.criterion`; OpenMX's test on dUele alone fired on a coincidence (RTX 5080, sidia333_col_cluster: dUele 7e-12 at step 15 with NormRD 4.3e-8, five steps early and 2e-9 Ha off). 0 = off. The band solvers also drop their warm-start bases when the SCF cycle ends, so the forces start with the device memory free (the resident bases of the NC band left Force3 without room on a 16 GB card) |
| `OPENMX_EIGEN_REFINE_UNBLOCKED` | 1 | The refinement products with the full GEMMul8 workspace when the device has room for it (about 1.7x faster than the blocked products at the 256 MiB cap); **0** = the blocked products |
| `OPENMX_EIGEN_FP32_TWO_STAGE` | 1 | The full FP32 solve of the refined eigensolver uses the two-stage cusolverDnXsyevd (CUSOLVER_ALG_2; cuSOLVER 12.3.4 and later; RTX 5080, n = 5616: 323 ms instead of 638), **0** = the one-stage cusolverDnXsyevdx. Since 2026-10-09 a two-stage solve that fails to converge (info > 0: sporadic on the RTX 5080, e.g. info=297 on a 2808 x 2808 band problem) is retried once with the one-stage algorithm from a fresh conversion of the FP64 matrix before the solver falls to FP64; before, one such failure left the rest of the SCF cycle in FP64 (sidia333 band_on D: Diagonalization 68 s to 95 s) |
| `OPENMX_EIGEN_REFINE_WARM_BAND` | 1 | Warm start of the refined eigensolver also in the band solvers (per k-point slot); 0 limits the warm start to the cluster solvers. |
| `OPENMX_EIGEN_REFINE_WARM_PERIOD` | 0 | Band warm start: every this many SCF steps a cold FP32 solve replaces the warm start (0 = never). |
| `OPENMX_EIGEN_REFINE_WARM_DELTA_FLOOR` | 1 | Keep the cold FP32 solve's cluster threshold delta as a floor for warm starts (their residual is far smaller, which would shrink the cluster chain to nothing); 0 drops the floor. |
| `OPENMX_EIGEN_REFINE_ALL` / `_COMPLEMENT` | 0 / 1 | Diagnostics of the refinement blocks: `_ALL=1` refines every eigenvector column instead of the occupied block, `_COMPLEMENT=0` drops the third product block that covers the complement of the refined columns. |
| `OPENMX_EIGEN_REFINE_CHECK` | 0 | Diagnostic: after the Rayleigh-Ritz step compute and print the residuals \|A x − λ x\| / \|x\| and the orthogonality of the refined vectors. |

| Variable | Default | Meaning |
|---|---|---|

| `OPENMX_SETHAM_GPU_RESIDENT` / `_FLOOR_MB` | 1 / 4096 or 16384 | Device residency of the SCF-invariant tables and the floor left free afterwards (default depends on whether a diagonalization need has been published; §7.7) |

| `OPENMX_SETHAM_STREAMING` | 1 | Streamed pair batches (256 MiB workspace per rank, `OPENMX_SETHAM_STREAM_MB`) when the device holds a single whole-rank allocation; **2** streams whenever it cannot hold every rank's (A100 emulation: 52 s against 165 s of the hybrid default and 37.6 s of the serial waves); **0** = off |
| `OPENMX_SETHAM_ONTHEFLY` | 1 | A rank whose orbital tables do not fit on the device evaluates the orbitals of every batch of atom pairs on the device (the device code of Set_Orbitals_Grid, orbs_grid_gpu.h) instead of computing on the CPU or streaming the tables: only its atoms' sphere indices stay resident (a few MiB) beside a batch workspace of `OPENMX_SETHAM_ONTHEFLY_MB` (default 128) MiB. The density of Set_Density_Grid takes the same tiles on such ranks. 0 = off (the CPU or the streamed path as before) The workspace of a rank is the smaller of that bound and its share of the plan's free device memory left after the staged wave's peak and a margin of `OPENMX_SETHAM_ONTHEFLY_MARGIN_MB` (default 0) MiB, without exceeding either the explicit workspace cap or the physical free-memory share (the budget comes from the plan, not from a reading taken while the staged ranks allocate, so every rank sees the same value). Oversized atom pairs use bounded overlap-point chunks; allocation failures retain the CPU fallback. When the device cannot hold every rank's tables, the plan shrinks the staged wave until each rank outside it gets its bound: the on-the-fly ranks, not the staged ones, set the time of the phase (RTX 5080: 1.4 s against 0.65 s per step). The on-the-fly state is released when the SCF cycle ends. The evaluation takes cos/sin of the angles straight from the coordinates and the radial mesh index from the logarithmic mesh (no bisection), which agrees with the host's Get_Orbitals to the last bits of the double value |
