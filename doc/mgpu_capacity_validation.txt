and host-backed multi-GPU MAGMA when they do not. gpusolver3 forces the

Large periodic overlap matrices exposed a MAGMA result-ordering issue:
the n=13000 real solve returned adjacent values 0.59793007123800646 and
0.59793007123800623. The adapter's exact ascending-order check correctly
rejected this 2.220446e-16 inversion. The adapter now sorts each returned
value together with its corresponding vector before applying the same
finite, residual and orthogonality checks; no tolerances were relaxed.
An in-place permutation uses one extra host column and O(n) indices. Real/complex,
upper/lower, vectors/values-only and cyclic/reversed return-order tests
pass against the independent diagonal-spectrum oracle. Nonfinite and
corrupt results still fail without publishing to the caller.

Full-size benchmark protocol
----------------------------
tests/run_mgpu_sidia_benchmark.py generates all 1000 coordinates of the
supplied 5x5x5 diamond supercell (5.431 Ang lattice), retaining
Si7.0-s2p2d1 / Si_PBE19, GGA-PBE, 200 Ry and one SCF step. The collinear
matrix order is 13000, the noncollinear spinor order is 26000. Noncollinear
inputs enable SOC. Cluster retains the supplied unit cell and uses the
Cluster solver at Gamma; this is not a vacuum-isolated Si nanocluster.
Band uses a periodic 2x1x1 GCenter mesh (two actual k-points), so four allocated GPUs form two
groups of two. This differs from the supplied 2x2x2 mesh specifically to
exercise cooperation within a k-point on the available four-GPU node.

Runs use one MPI rank, 32 OpenMP threads and 32 BLAS threads, with FP32
refinement disabled. The cuSOLVER baseline disables cooperation while
keeping the same allocation; forced MAGMA uses gpusolver3. Automatic
noncollinear runs use gpusolver with native workspace admission enabled;
they do not set OPENMX_MGPU_MEMORY=host or inflate the native reserve.
With one MPI rank the two Band k-points execute sequentially, each on its
own two-GPU group. These timings measure within-matrix cooperation; they
do not measure simultaneous k-point execution by two MPI owner ranks.

Report application total and external elapsed time separately. One-SCF
measurements include initialization and force evaluation and are not
steady-state SCF scaling measurements. Results retain the binary and
input hashes, all runtime controls, energy components, every force
component, process-tree RSS samples and actual worker lists. The host
guard is 210 GiB within the 240 GB PBS allocation. GPU samples are taken
every five seconds and therefore give sampled, not instantaneous, peaks.

Reproduction within a four-GPU allocation (run the large cases sequentially):
  python3.9 tests/run_mgpu_sidia_benchmark.py --binary source/openmx \
    --output /new/col-cluster --cases cluster_col --modes single magma \
    --gpus 4 --threads 32 --blas-threads 32 --timeout 650
  python3.9 tests/run_mgpu_sidia_benchmark.py --binary source/openmx \
    --output /new/col-band --cases band_col --modes single magma \
    --gpus 4 --threads 32 --blas-threads 32 --timeout 650
  python3.9 tests/run_mgpu_sidia_benchmark.py --binary source/openmx \
    --output /new/nc-cluster --cases cluster_nc --modes hybrid \
    --gpus 4 --threads 32 --blas-threads 32 --timeout 1600
  python3.9 tests/run_mgpu_sidia_benchmark.py --binary source/openmx \
    --output /new/nc-band --cases band_nc --modes hybrid \
    --gpus 4 --threads 32 --blas-threads 32 --timeout 1600

"hybrid" names the benchmark's gpusolver mode: it prefers cuSOLVER, enables
cooperative products, and automatically admits host MAGMA if memory is
insufficient. "magma" selects gpusolver3; "single" disables cooperation.
No OPENMX_MGPU_MEMORY override is used by these commands.
