GPU work outside the generalized eigenproblem (experimental)
===========================================================

The main collinear/noncollinear Cluster and Band paths can distribute their
existing GPU kernels outside the solution of the generalized eigenproblem
across the permitted devices. This distribution is experimental and off
by default: on the measured Si1000 runs it made the whole run slower (see
gpu_workers_validation.txt). OPENMX_GPU_WORKERS=1 (or on) enables it;
without it every rank keeps this work on its own GPU. The eigensolver and
its matrix products follow their own capacity rungs (cluster_mgpu.txt):
the default gpusolver uses cuSOLVER when its matrices/workspaces fit and
recovers through host-backed MAGMA on memory shortage. gpusolver3 always
selects MAGMA. gpusolver2 retains the separate ELPA/COSMA implementation.

Ownership
---------
scf.Gpu.Num, CUDA_VISIBLE_DEVICES, scf.mgpu.enable and OPENMX_MGPU_NUM_GPUS
bound the pool. The pool is the permitted GPU set of the rank's own node,
also when the run spans several nodes: every rule below then holds per
node, with the ranks of that node (workers never call MPI and only take
node-local ordinals and locks). In a two-node job with one GPU per node,
the ranks of each node work on that node's GPU, so both GPUs are busy; with
more GPUs than ranks on a node, the free GPUs of the node become workers of
that node's ranks. Band k-point groups remain single-node; the cluster
capacity path is described in cluster_mgpu.txt. Band dense work uses exactly the current k-point group:
floor(G/K) devices per computed k-point, only when that quotient is at least
two. Thus K=3/G=4 does not cooperate and K=3/G=8 uses six devices.

Atom-local/grid-local work keeps every MPI rank's established GPU. Devices
not occupied by another local rank are assigned cyclically to local ranks.
This preserves MPI domain decomposition and avoids duplicate accumulation.
A rank-owned global service may use the entire permitted pool. If all GPUs
already have ranks, the ranks continue to perform their local work on their
own GPUs. No worker invokes MPI. UUID-ordered interprocess admission uses
the same locks as cooperative diagonalization and GEMM.

Distributed operations
----------------------
- Orbital tables and on-the-fly atom/pair/chunk orbital evaluation.
- Atom/grid overlap lists, nonlocal radial integrals, VNA integrals and
  projector contractions; the opt-in overlap/kinetic radial GPU kernel.
- Hamiltonian base terms and local-potential matrix elements, including
  resident, streaming and on-the-fly CUDA/OpenACC paths.
- Density grid construction, with exclusive output-grid ownership for
  local CSR, rank-owned global CSR and on-the-fly contractions.
- XC grid evaluation, including gradient/divergence halos and NC rotation.
- Existing GPU total-energy terms, dipoles, force contractions and reductions.
- GPU RMM-DIISH residual history, Gram matrices and optimum residuals.
- Dense sparse-to-full assembly, spinor assembly, scaling, transposition,
  Hermitian symmetrization, eigenvector packing, sparse DM/EDM extraction
  and real/complex matrix products.

Each element or atom has one owner, or contributes to a private partial
reduction combined in a fixed order. State summations and GEMM's complete
K dimension remain on one worker. Existing GeForce precision choices and
A100 native FP64 choices are preserved. Operations that were CPU-only are
unchanged. A task with fewer independent items than devices uses only the
number of devices on which it can place nonempty work.

Memory and lifetime
-------------------
Worker inputs use read-only peer access when available. Otherwise bounded
copies or private input views are used. Accumulating outputs remain private
until all workers finish. Disjoint overwrite-only tables can be filled
directly; a failed attempt rebuilds the complete table through its original
fallback. CUDA/OpenACC device bindings and the caller's dense scope
are restored. Orbital caches are released on every device when their grid
frame expires. Residual history is sharded across workers rather than
replicated. Cooperative GEMM can stage its private full result on the host
when the owner GPU lacks room for an additional full matrix.

Recoverable preflight/allocation failure leaves accumulating results
unchanged for the existing fallback. Publication/synchronization failures
are errors, because retrying an already partly committed sum is unsafe.
Automatic eigensolver memory recovery retains its stricter contract: it
must succeed within the allowed GPU pool or terminate with an error.

Controls and validation
-----------------------
The distribution is off unless OPENMX_GPU_WORKERS=1 (or on); unset, 0 or
any other value keeps the original single-device auxiliary kernels. This
is independent of OPENMX_MGPU_GEMM and the solver selector.
OPENMX_GPU_WORKER_COPY=1 exercises copies without peer views.
OPENMX_MGPU_VERBOSE=1 reports operation names, nonempty item counts and
actual worker device lists. A device-resident matrix product stays on its
owner's GPU by default, like the eigensolver; OPENMX_MGPU_GEMM=on spreads
it over the permitted GPUs for every size and auto with the older
size/NVLink heuristic (both experimental).

Host-only ownership/rollback checks:
  python3 tests/run_gpu_workers_cpu.py
  python3 tests/run_gpu_meminfo_cpu.py
  python3 tests/run_mgpu_runtime_cpu.py
  python3 tests/run_mgpu_gemm_cpu.py
  python3 tests/run_gpu_dense_workers_cpu.py
  python3 tests/run_setham_density_fallback_cpu.py

Four-GPU transform/DM numerical oracle (NVHPC OpenACC and CUDA required):
  bash tests/run_gpu_dense_workers_smoke.sh
Set CUDA_HOME, CUDA_MATH_ROOT, NVHPC_CC, NVHPC_CXX, CUDAHOSTCXX and MPI_INCLUDE
when these are outside PATH. OPENMX_GPU_TEST_COMPILE_ONLY=1 builds without
starting a CUDA context; OPENMX_GPU_TEST_BUILD selects the output directory.

CUDA/OpenACC quadrature and output-ownership oracles:
  bash tests/run_setham_point_chunks_gpu.sh
  bash tests/run_set_hamiltonian_stream_smoke.sh
  bash tests/run_gpu_setham_workers_smoke.sh
These use the same toolchain variables as the dense oracle. The first checks
FP64/DF compact tiles, 96 guarded output ranges and actual CUDA/OpenACC
prepare/execute failure rollback with fixed/dynamic CPU teams. SETPOINT_SANITIZE=1
or SETHAMILTONIAN_SANITIZE=1 additionally enables CUDA memory checking.
The last oracle compiles the actual OpenACC base/quadrature workers and
compares them to host arithmetic, including spin components, core-hole and
Hubbard terms, split pair boundaries, output guards and peer/copy transfers.

Four-mode SCF/force regression, with a retained baseline executable:
  python3 tests/run_gpu_workers_regression.py --baseline /path/to/baseline \
    --binary /path/to/candidate --output /new/output/path --gpus 4
The harness records exact binaries, inputs, controls, energies, energy
components, forces and worker ownership. Use --ranks/--threads for MPI
layouts, --fp32/--env for precision and resident/streaming variants, and
--mixing rmm-diish --scf-iterations 7 --env OPENMX_MIXH_GPU=1 for history
rotation. A completed test must show actual cooperative work, not only a
successful executable exit.

The implementation does not imply that every small kernel is faster with
more GPUs. Transfer, launch and reduction costs must be included when
comparing timings. Completed measurements are recorded separately from
implementation descriptions.
