their original launch settings are retained and per-rank verification is
marked unavailable in runs.json. No upstream runs were repeated.

The detailed NVHPC/CUDA/GCC and MPI tool selections match
doc/pegasus_refactor_validation_20261027.txt, with the current source pin.
Host D3 validation passed 33 interpolation/gradient cases and 32 production
energy/coordinate-gradient/strain cases, including the missing-gradient
negative control. Those tests exercise the newly included D3 optimization.

For a fresh run directory, CPU uses OPENMX_GPU=0 and scf.eigen.lib=elpa2;
GPU uses OPENMX_GPU=1 and the original gpusolver input. OpenMP, MKL and
OpenBLAS thread controls are 2, dynamic teams disabled, OMP_PLACES=cores,
OMP_PROC_BIND=close. Open MPI maps ppr:24:node:PE=2 and binds to cores.
The MPS control/server starts before application launch on every GPU node.
Full inputs are used: -runtest runs its 14 cases in one MPI invocation.
The named inputs run three CPU/GPU pairs with the second pair GPU-first.
Each pair occupies its own node; no simultaneous CPU/GPU run shares a node.
All source input/data hashes match the prior snapshots. The original MD/SCF
limits and convergence criteria are unchanged.

L/L2/L3 reuse completed earlier measurements with explicit source/binary
identities. Their timings are not measurements of the refreshed executable.
Upstream uses the earlier Intel icx/ifx 2025.3.2, Intel MPI 2021.17 and
MKL 2025.3 build of official OpenMX 4.0 + patch 4.0.1 (2026-05-08).
Upstream L2 remains excluded at the user request. Partial or cancelled
runs never contribute a suite total.

Numerical acceptance: absolute energy <=1e-7 Ha, maximum absolute individual
force component <=1e-7 Ha/bohr, matching atoms and grids; printed coordinate
rounding <=1.000001e-5. Native runtest force sums are not this criterion.
Sidia333 stops at its 25-SCF limit; L3 uses fixed three-SCF inputs.
SCF counts differ elsewhere; full-run speed ratios include these differences.
Elapsed.Time is used consistently; launcher wall times are separate columns.
Resource monitoring samples every 2 seconds with a 4 GiB available-memory
guard. RSS sums include shared pages, so they are not unique memory usage.
