Single-node multi-GPU Band calculations
======================================

GPU allocation
--------------
Ordinary collinear and noncollinear Band use the same cooperative GEMM,
MAGMA eigensolver implementation as Cluster under gpusolver and gpusolver3.
Let K be the number
of k-points actually evaluated, and G the available GPU count after
CUDA_VISIBLE_DEVICES, scf.Gpu.Num and OPENMX_MGPU_NUM_GPUS limits.

  GPUs per k-point q = floor(G / K)
  Participating GPU pool = q * K

Cooperation requires q >= 2. Each k-point k gets CUDA-visible ordinals
[k*q, (k+1)*q). The last G-q*K GPUs are excluded. Spin-up and spin-down use
the same group for a given k-point; spin does not multiply K.

  Computed K    Available G    GPUs/k-point    Used pool    Cooperation
       3             4              1              -       disabled
       3             8              2              6       enabled
       2             4              2              4       enabled
       1             4              4              4       enabled

For the 3/8 example the groups are [0,1], [2,3], [4,5]. Devices 6 and 7
are excluded from this input's rank GPU pool before CUDA/OpenACC caches
are created. These ordinals are relative to CUDA_VISIBLE_DEVICES, never
absolute system GPU indices. Each group currently supports up to 8 GPUs;
an unsupported larger q declines rather than silently changing the rule.

K is not always the product in scf.Kgrid. Collinear regular and Gamma-centred
meshes reduce k/-k pairs; generated special lists use their actual length.
Noncollinear Band evaluates the full mesh. A 1x1x1 mesh is converted by
existing input handling to periodic Cluster, whose cooperation is governed
by cluster_mgpu.txt. This change preserves that convention.

Use and selection
-----------------
Example for two actual collinear k-points with a regular 4x1x1 mesh:

  scf.EigenvalueSolver   band
  scf.eigen.lib         gpusolver3
  scf.Generation.Kpoint Regular
  scf.Kgrid            4 1 1
  scf.Gpu.Num          4
  scf.mgpu.enable      on

For two noncollinear k-points use scf.SpinPolarization=nc and a 2x1x1 mesh.
The default gpusolver keeps cuSOLVER while the dense buffers fit. Memory
exhaustion automatically selects the host-backed multi-GPU MAGMA path.
gpusolver3 forces MAGMA even when one GPU would have enough memory.
Both honor the exact q*K allocation and scf.Gpu.Num upper bound. If q<2,
MAGMA is unavailable or the selected GPUs cannot hold the required scratch,
a forced / capacity solve reports the reason and uses the CPU. gpusolver2 remains
distributed ELPA/COSMA. Input off disables cooperation.

Device-resident GEMM stays on its owner by default. Optional cooperative
GEMM and k-dependent dense kernels use the same k-point group;
OPENMX_MGPU_GEMM=on enables all sizes and auto uses the shape/NVLink policy.
Other GPU phases recover capacity locally, across nodes, then on the CPU,
as described in gpu_workers.txt.
The optional OPENMX_MGPU_SOLVER=auto timing experiment applies only to
ordinary device-resident gpusolver solves. It is not the default and never
overrides gpusolver3 or the capacity fallback. cuSOLVERMg/Mp is not used.

MPI ranks, storage and synchronization
-------------------------------------
Every rank must see the same allocated GPU pool. The input trims the global
rank limit to q*K before GPU initialization, retaining rank-stable CUDA and
OpenACC devices. MPI may have fewer ranks than k-points; a rank then visits
the appropriate group as it processes each k-point sequentially.

On the ordinary cuSOLVER path, the owner keeps dense buffers on its GPU.
On the MAGMA capacity path, dense matrices and vectors stay on the host;
eigensolver scratch is distributed and matrix products use bounded tiles.
The owner GPU may be outside the current k-point's worker group but is
inside the truncated pool. GPU UUID locks cover workers and owner.
Capacity work is scheduled one dense turn at a time to bound memory.
The same k-point grouping applies to the density-matrix products.

Narrow scopes surround only one-k-point dense work, including both passes
and refinement completion. Existing MPI turn scheduling and all-k-point
chemical-potential collectives remain outside these scopes. DC, LNO,
generalized-Bloch NonCol Band and distributed ELPA/COSMA are unchanged.
Existing refinement and GEMMul8 policies remain effective on the native
path. The host-backed capacity path uses FP64 without a cuSOLVER workspace.

MAGMA device groups and build
----------------------------
Stock MAGMA's one-stage _m routines enumerate logical devices from zero.
The pinned MAGMA 2.10.0 build applies a small private CUDA-interface patch
that maps those logical IDs to the selected physical-visible group. The
map is process-wide for MAGMA's OpenMP threads, immutable during a solve,
and protected by the adapter mutex. It is cleared before returning,
including failures. CUDA visibility and application CUDA calls are never
remapped. Archive and interface hashes are verified, and patch application
is exact and idempotent.

  cd source
  make -f Makefile.kugui -j2 openmx WITH_MAGMA=1

Rebuild with WITH_MAGMA=1 to update an existing local install. WITH_MAGMA=auto
only links an existing install. An unpatched external MAGMA can still serve
prefix groups [0,1,...]; nonprefix groups report unavailable and forced or
capacity solves then use CPU recovery. WITH_MAGMA=0 retains native cuSOLVER
and custom GEMM, with CPU recovery when the dense GPU work cannot fit.
The experimental paper backend has been removed. The gpusolver keyword includes automatic memory recovery through MAGMA;
gpusolver3 forces it and gpusolver2 remains the distributed ELPA/COSMA selector.

Diagnostics and validation
--------------------------
The input prints the effective Band pool when enabled. OPENMX_MGPU_VERBOSE=1
or level.of.stdout >= 2 adds scope, k-point, K, worker IDs, group size,
used pool and owner to operation reports. The reported GEMM active count
must equal q to demonstrate actual participation.

CPU allocation checks:
  python3 tests/run_mgpu_band_plan_cpu.py
  python3 tests/run_mgpu_band_group_cpu.py

The plan fixture enumerates inversion orbits independently, including spin,
special meshes and overflow. Group tests cover the 3/4 and 3/8 examples,
scope restoration and input/node gates with simulated devices.

Full OpenMX comparisons inside a four-GPU single-node allocation with MPI
and MPS configured by the caller:
  python3 tests/run_mgpu_band_regression.py \
    --baseline /path/to/pre-band-mgpu/openmx --binary source/openmx \
    --output /new/result/directory --ranks 4 --gpus 4 --kpoints 2

Use --ranks 1 to exercise sequential k-points and owners outside worker
groups. --kpoints 3 --gpus 4 --backends off auto checks mandatory decline
on the native path. Forced gpusolver3 must instead exit if no cooperative
group exists; run_mgpu_capacity_regression.py checks that error policy.
The fixture uses B2C62_Band, three SCF steps, and compares total
energy and every force component; it requires correct worker lists and
successful solver/GEMM operations for every k-point. It is a correctness
test, not a whole-SCF performance measurement.

To exercise existing FP32 refinement across the native scopes, add
--backends off auto --scf-iterations 5 --fp32 on --refine 2 --warm 1
--require-refinement. The forced MAGMA capacity path always uses FP64.
The smaller --template tests/data/B2C14_Band.dat fixture retains the same
basis and potentials in a 16-atom periodic diamond cell; its Col/NonCol
matrices have dimensions 208/416, keeping force evaluation inexpensive.
Use col_off and noncol_soc with --ranks 1 for sequential k-points, and
--ranks 4 for resident per-k-point work. Add --max-concurrent-k 1 to the
four-rank case to force staged refinement. The fixture checks that Band
actually entered refinement; merely setting the environment is insufficient.
The final SCF step retains the existing FP64 policy. A one-rank col_on case
does not enter refinement under the existing implementation.

For direct eigensolver-hook checks, build tests/run_mgpu_solver_smoke.sh
after installing the patched MAGMA library. Its --band-kpoints and --owner
arguments exercise group changes with an owner outside the worker group.
Add --require-backend with forced magma to reject a silent native
fallback; omit it for auto, disabled and q<2 tests.

They retain their original binary provenance and backend names.
