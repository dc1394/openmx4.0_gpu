DC-LNO GPU binding correction, 2026-10-31
========================================

CG15c-DC-LNO and N1C999 failed in their GPU paths with 32 MPI ranks,
two OpenMP threads per rank, two visible A100 GPUs and NVIDIA MPS.
Both logs contain 16 CUDA_ERROR_INVALID_HANDLE failures in
SOG_Device_EvalAtomTile_Part, after the first DC-LNO eigenproblem.

DCLNO_GPUProxy_Init selected node_rank % ngpu, while the shared CUDA and
OpenACC binding uses contiguous blocks of node-local MPI ranks by default.
For 32 ranks and two GPUs, ranks 0..15 initially use GPU 0 and ranks
16..31 use GPU 1. DC-LNO's modulo selection moved 16 ranks to a different
device after their per-device orbital tables/runtime state were prepared:

  Local rank    Shared default device    Former DC-LNO device
       1                  0                       1
      16                  1                       0

The initialization now uses openmx_gpu_map_rank_to_device with the same
launcher-local rank and size as the other CUDA/OpenACC binding sites.
This also preserves the original device when the solver communicator is
only a subset of the node's MPI ranks. scf.gpu.num remains the upper bound;
OPENMX_GPU_RANK_MAP=mod continues to select the common modulo map.

The change is in source/Divide_Conquer_LNO.c. The orbital evaluation and
numerical algorithms are unchanged.

Validation
----------
tests/run_dclno_device_binding_cpu.py extracts the production DC-LNO
initializer and the production common rank map, with MPI/CUDA boundaries
stubbed. It checks the pre-existing CUDA/OpenACC assignment is preserved,
device caps, block/modulo maps, uneven rank counts, communicator subsets
and initialization reuse. The original initializer fails the assignment
check. The repaired initializer passes all 7,224 binding checks.

The NVIDIA build and installation completed with Makefile.kugui,
NVHPC 24.7 / CUDA 12.5, GCC 12.2 and site Open MPI 4.1.6.

with exit status zero on acc008 at 09:05:20 JST on October 31.
